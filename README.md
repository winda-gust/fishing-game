# 釣り日和 🎣

日本語で遊べる、シンプルなブラウザ魚釣りゲームです。出会う魚は運で決まり、釣り上げられるかはタイミングと「巻く・休む」の判断で決まります。HTML・CSS・JavaScriptだけで動く静的サイトで、ゲーム本体に外部ライブラリ、画像のダウンロード、APIキーは必要ありません。

## 起動方法

### ブラウザで直接開く

リポジトリ内の `index.html` を Chrome、Edge、Firefox、Safari などの最新ブラウザで開いてください。インストール不要で、オフラインでも遊べます。

### 開発用サーバーを使う

Python 3 がある場合、リポジトリのディレクトリで実行します。

```sh
cd fishing-game
python3 -m http.server 8000 --bind 0.0.0.0
```

ブラウザのアドレス欄に `http://localhost:8000` を入力してください。サーバーは `Ctrl+C` で停止できます。Node.js と npm もある場合は、同じディレクトリで `npm start` を使えます。クラウド環境での作業ディレクトリは `/workspace/fishing-game` です。

## 遊び方

1. **「投げる」** を押し、一度離します。水面にウキが現れ、約2～3.8秒で本当の食いつきが来ます。
2. **「何かがつついている……」** は小さな反応です。まだ押さず、待ちましょう。
3. ウキが大きく沈み、**「食いついた！ 今だ！」** と出たら、**1.8秒以内に新たに「合わせる」を押します**。投げたままの長押しやキーリピートでは合わせられません。
4. 合わせに成功したら、**一度離してから押し直します**。押している間は巻き、離している間は休みます。連打は必要ありません。
5. **落ち着いているときは巻く／「魚が身をよじった！」という予兆が出たら離す**のが基本です。離せば巻く動作はすぐ止まり、**0.3秒続けて休むと張りの回復が始まります**。短い休憩を足し合わせても回復せず、押し直すと次の回復待ちは最初からです。休んでいる間は釣り上げゲージを維持します。
6. 釣り上げゲージが100%になれば成功です。魚の名前を表示し、匹数・得点・履歴・図鑑を一度だけ更新します。釣っている間は名前を伏せ、魚影と引きの強さを表示します。
7. 結果を見たら、ボタンを離し、**「もう一度投げる」** で次の釣りを始められます。

マウス、スマートフォンのタッチ、キーボードに対応しています。キーボードでは `Tab` でメイン操作ボタンを選び、`Space` または `Enter` を押す・長押しする・離すことで操作します。操作ボタンの外で離したり、タッチがキャンセルされたりしても巻き続けません。ボタン上では長押しによる文字選択・スクロールを防ぎ、ボタン以外ではページをスクロール・拡大できます。音は不要です。

### 失敗したとき

- **早すぎた：** 小さなつつきや待機中に押しています。ウキが大きく沈むまで待ちましょう。
- **遅かった：** 本当の食いつきから1.8秒を過ぎています。「食いついた！」を見たら新たに押しましょう。
- **糸が切れた：** 張り100%で巻いた危険時間の合計が0.9秒に達しています。離すと危険時間は止まるので、回復待ち中に糸切れにはなりません。ただし、短い解放や一瞬100%未満になるだけでは、使った猶予は戻りません。**休んで張りを70%以下に下げると危険が解除されます**。例えば700ms使って一瞬離した場合、残りは200msのままです。

失敗時には釣果・得点・図鑑を更新しません。巻き上げ中に全体制限時間はなく、休み続けても魚は逃げません。**暴れている間に巻くと、張りが増えて釣り上げゲージも少し戻ります**。離していれば戻りません。回復待ち、危険が残っていること、残り猶予を画面に表示するので、落ち着くまで十分休んでから再び巻きましょう。

### 中断・リセット

タブ切替や画面ロックでページが非表示になったとき、またはウィンドウがフォーカスを失ったときは、進行中の釣りを一時停止し、長押しを解除します。停止中は反応猶予・魚の行動・ゲージ・回復待ち・累積危険時間が進みません。戻ったら **「準備して再開」** を押して離し、その後に合わせる・巻く操作を行ってください。合わせ・再開を押したままでは巻いたり張りを回復したりしません。再開操作や非表示の時間で残り猶予が回復することもありません。

**「リセット」** は釣果・得点・図鑑をゼロに戻し、進行中の釣りも終了します。どの段階でも使えます。釣果はページを開いている間だけ保持され、再読み込みするとリセットされます。保存機能は追加していません。

### 魚と得点

| 魚 | 得点 | 出会う確率 |
| --- | ---: | ---: |
| アジ | 10 pt | 35% |
| イワシ | 15 pt | 25% |
| サバ | 20 pt | 20% |
| タイ | 50 pt | 12% |
| マグロ | 100 pt | 6% |
| 金の魚 | 300 pt | 2% |

投げるたびに一度だけ独立して抽選します。途中で種類を引き直さず、操作と無関係なランダム失敗もありません。既存の出現確率・得点を維持しています。同じ魚も何度でも釣れ、成功時の得点は累積します。

### 魚ごとの特徴と調整値

「落ち着く → 暴れる予兆 → 暴れる」を繰り返します。次の値は秒、およびゲージのパーセントポイント／秒です。

| 魚 | 特徴 | 落ち着く／予兆／暴れる（秒） | 巻き上げ速度 | 張り増加：落ち着く／予兆／暴れる | 暴れ中の後退速度 |
| --- | --- | --- | ---: | --- | ---: |
| アジ | 落ち着く時間が長く、基本操作の練習向き | 3.0／1.0／1.6 | 18 | 14／22／50 | 4 |
| イワシ | 軽い引きで巻きやすく、暴れも短め | 2.3／0.85／1.1 | 21 | 13／20／50 | 4 |
| サバ | 短い暴れを頻繁に繰り返す | 1.45／0.8／0.9 | 19 | 20／25／58 | 5 |
| タイ | 力強く引き、丁寧に巻く必要がある | 2.0／1.0／1.6 | 14 | 21／28／65 | 5 |
| マグロ | 重い引きで、暴れる時間も長い | 1.8／1.15／2.1 | 12 | 24／30／75 | 6 |
| 金の魚 | 最も強い引き。長めの予兆で早く休もう | 1.6／1.2／2.4 | 13 | 26／36／85 | 7 |

巻き上げ速度は落ち着いているときの値です。予兆中は45%、暴れている間は表の後退速度で戻ります。全種類共通で、合わせ直後の張りは20%、0.3秒の継続休憩の後は毎秒28ポイント下がります。回復待ち中の時間を後からまとめて回復に使うことはありません。休んでいる間の釣り上げゲージ減少はありません。短いミスで全進捗を失わない後退量にし、クリック回数で罰する処理は設けていません。

反応猶予は初期値の **1.8秒**、糸切れ猶予は **0.9秒** です。文字・ウキの沈み・魚の動き・ゲージを併用して知らせ、色だけに頼りません。

## テスト

### ゲームロジック

Node.js 20以上が必要です。外部パッケージをインストールせずに実行できます。

```sh
npm test
```

乱数を注入し、経過時間を明示して進めるため、運任せのテストにはなりません。抽選・得点の維持、早押し／時間切れ／合わせ成功、長押しの持ち越し防止、全6種類の成功と糸切れ、回復待ち300msの境界、危険の保持と70%での解除、暴れ中の時間比例の後退、重複入力、得点の一度だけの加算、中断・リセット、細かい／大きい時間刻みと30・60・120fps相当の一致などを確認します。

### 実際のブラウザでの操作

ブラウザテストには、開発用依存関係の Playwright と Chromium が必要です。

```sh
npm ci
npx playwright install chromium
npm run test:browser
```

すでに Chromium がインストールされている場合、ブラウザのダウンロードを省略できます。テストは `/usr/bin/chromium` を自動的に使い、ほかの場所にある場合は `CHROMIUM_PATH` で指定できます。

```sh
CHROMIUM_PATH=/path/to/chromium npm run test:browser
```

テストは一時的なローカルサーバーを自動で起動します。テスト内だけで乱数・時計を制御し、実際のDOMとブラウザ入力を使って、全6種類の成功／糸切れ、早押し／時間切れ、得点・履歴・図鑑、再挑戦、各段階のリセット、マウス・タッチ・キーボード、ボタン外での解放、キーリピート、中断／再開、幅320px・375px・PCの表示、JavaScriptエラーの有無を確認します。開発用サーバーを別途起動する必要はありません。テスト用の魚固定・時計制御はゲーム本体に組み込んでいません。

非表示・復帰はヘッドレスブラウザでイベントを模擬して確認します。実際のOSによる画面ロックやバックグラウンド化、実機スマートフォンの確認とは区別してください。

試遊では開発用サーバーを起動し、時計を固定せず、早押し・時間切れ・押しっぱなしの糸切れ・予兆に合わせた巻く／休むによる成功を確かめてください。幅320px・375pxではブラウザの端末表示を使い、2本のゲージ・危険表示・メイン操作ボタンが同時に読めることも確認してください。

このクラウド環境では Chromium の管理ポリシーが `file://` を制限しているため、実際の画面操作は HTTP 経由で検証しています。同様の制限があるブラウザでは、開発用サーバーを使ってください。

### 連打対策の比較・通常速度のブラウザ検証

```sh
node scripts/compare-reeling.cjs
node scripts/verify-reeling-browser.cjs
```

比較スクリプトは基準コミット `fd40855c90024718a3f7df887f4355661b266c64` と現在の `game-core.js` を読み、全6種類、複数の開始ずれ、状態判断と150～250msの反応遅れ、指定の固定リズム、回復境界、100%付近の短い解放を同じ条件で計測します。基準コミットを含むGit履歴が必要です。180秒は計測の観測上限であり、ゲームの制限時間ではありません。未決着は糸切れと区別します。

通常速度のブラウザ検証はPlaywrightとChromiumを使い、仮想時計を使わずにマウス・タッチ相当・Space・Enterを自動操作します。ブラウザの操作やOSの処理に時間がかかるため、固定リズムの指定値と実測の押下時間は区別して記録します。魚の固定は検証側の最初の抽選だけで、本番機能にはしません。

集計・CSV・ブラウザ結果と必要な画像は `reports/` に保存します。実機スマートフォン、人間の初心者による試遊、実際の画面ロックとは別の検証です。詳細な結果・最終コミット・反映状態は同ディレクトリの日本語報告書を参照してください。

### 公開版・修正ブランチを確認する

[公開サイトはこちら](https://winda-gust.github.io/fishing-game/?v=f01eeed) です。連打対策のコードはmainへ反映済みで、Pagesの公開処理が成功した後にサイトへ反映されます。修正時のコードと検証結果は `fix/reeling-anti-spam` ブランチにも保存しています。PCで手元のファイルを確認する場合は、Node.js/npmとPython 3を用意し、新しいフォルダへ取得します。

```sh
git clone --branch fix/reeling-anti-spam https://github.com/winda-gust/fishing-game.git fishing-game-review
cd fishing-game-review
npm start
```

同じPCのブラウザでポート8000を開いてください。GitHubのブランチ画面でHTMLを開くとコード表示になります。スマートフォンのChatGPT入力欄に起動コマンドを貼ってもサーバーは起動せず、スマートフォン自身のlocalhostからクラウド環境には接続できません。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | 日本語の画面、海辺のSVG、ウキ・魚影・2本のゲージ・操作案内 |
| `styles.css` | レイアウト、スマートフォン対応、食いつきと魚の予兆のアニメーション |
| `game-core.js` | 魚のデータ・調整値、抽選、釣りの状態・経過時間・成功判定・釣果管理 |
| `app.js` | 押下／長押し／解放、中断と再開、描画時計、画面と図鑑の更新 |
| `favicon.svg` | ブラウザタブのアイコン |
| `tests/game-core.test.cjs` | Node.js標準テストによるロジック検証 |
| `tests/browser.test.cjs` | Playwrightによるブラウザ操作の検証 |
| `scripts/compare-reeling.cjs` | 修正前後の連打・バランス比較と合否検証 |
| `scripts/verify-reeling-browser.cjs` | 通常速度でのブラウザ入力と表示の検証 |
| `reports/` | 日本語報告書、比較の集計・CSV、ブラウザ結果と必要な画像 |

魚の種類・得点・出現率は `game-core.js` の `FISHES`、魚ごとの行動・引きの強さ・暴れ中の後退速度は `FISH_BEHAVIORS`、反応猶予・糸切れ猶予・継続休憩の待ち時間・安全な張りの閾値・張り減少などは `CONFIG` にまとめています。ゲージはフレーム数ではなく経過時間で進みます。動きを減らす端末設定にも対応し、食いつき・予兆・結果は文字でも表示します。画面は状態をライブ領域で通知し、ゲージには名前と数値を付けています。
